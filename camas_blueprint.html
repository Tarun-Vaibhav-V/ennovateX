Problem Understanding

Modern smartphones running agentic and GenAI workloads suffer from reactive memory management — the OS only acts after a crisis, not before one. On our Samsung S23 baseline traces:

Kill storms: 77 LMK kills in 45s means the system is thrashing — evicting apps it will need again in seconds
Cold-start penalty: A 3-second white screen when opening Gallery on an 8 GB flagship is unacceptable
Zero prediction: Android's LMK has no model of what the user will open next — it evicts blindly by OOM score

Technical Architecture — Data Flow & System Design
SLIDE 04
5-Layer System Architecture
L1

Data Collection — Perfetto Trace Ingestion

Captures sys_stats, memreclaim, am events at 1s poll. Produces structured JSON: {ts, app_id, rss_mb, psi_some, psi_full, lmk_events}

/proc/meminfo ActivityManager hooks PSI nanosecond counters ground_truth.json
L2

Feature Engineering — Time-Series Builder

11 engineered features including mem_velocity (ΔMemAvailable/Δt), psi_acceleration (2nd derivative), app_sequence sliding window (last 5 apps)

Raw JSON traces Feature matrix [10 timesteps × 11 features] Windowed dataset (2s lookahead)
L3

Context Predictor — LSTM + Markov Ensemble

LSTM(32 hidden) → Softmax(N apps). Fallback to Markov chain when entropy > 2.0 nats. Quantized INT8 for <3ms inference.

Feature matrix P(next_app_k) top-5 Confidence score
L4

Policy Engine — State Machine Controller

4 states: MONITOR → PRELOAD / EVICT_PRELOAD / EMERGENCY. Score = 0.25·freq + 0.35·recency + 0.40·P(next_access)

Confidence scores PSI rate, LMK count PRELOAD / KEEP / COMPRESS / EVICT
L5

Monitoring — KPI Measurement & Feedback

adb shell am start -W captures real TTI. Outcome logger feeds back into feature pipeline for continuous personalization.

Execution outcomes 7 KPI dashboard Model retraining signal

Novelty & Innovation
SLIDE 05
CAMAS is the first system to treat on-device memory management as a sequence prediction problem — not a resource accounting problem. Proactive, not reactive.
State-of-the-art vs CAMAS
Existing ApproachLimitationCAMAS Innovation
Android LMK (Low Memory Killer) Reactive only — kills after OOM. No prediction. Causes cold-starts. PSI-aware proactive eviction before OOM. Preserves predicted-next apps.
Static LRU Cache Evicts by recency only. Thrashes on cyclic patterns (work→maps→work). ML-scored: score = freq + recency + P(next_access). Cycle-aware.
Android App Standby Buckets Coarse, time-based. Not personalized. Not real-time. Personalized LSTM per user. Real-time P(next_app_k) updated each session.
Static KV Cache Fixed size. No awareness of multi-model GenAI workloads under pressure. Unified arbiter: single policy for both app cache and ML inference cache.
Novel signal

mem_velocity

ΔMemAvailable / Δtime — a first-derivative pressure signal. Captures how fast memory is being consumed, not just the current level. Enables prediction 2–3 seconds before OOM.

2nd derivative: PSI acceleration
Novel architecture

Dual-model ensemble

LSTM for complex sequences (high confidence). Markov chain fallback when entropy > 2.0 nats. Conservative mode when both are uncertain. No unnecessary preloading under ambiguity.

Graceful degradation built-in
Novel evaluation

Cross-device generalization

Train on Samsung S23 (Snapdragon). Evaluate on Nothing Phone 2a (MediaTek). Different chipsets, different OEM layers. Generalization across architectures is publishable-level evidence.

SLIDE 07

LSTM Predictor

PRIMARY — Trained by us

2-layer LSTM (hidden=32), Softmax head over N apps. Trained on our real Perfetto traces + augmented synthetic data. Exported to ONNX → INT8 quantized for <3ms on-device inference.

# Architecture Input: [app_seq(5), mem_velocity, psi_trend] × 10 steps LSTM(32) → Dense(64) → Softmax(N_apps) Output: P(app_1),...,P(app_N) # ≥75% top-1 target

Markov Chain (Baseline)

Built by us

Personalized transition matrix per user: P(next_app | current_app, time_of_day). Works with as few as 20 transitions. Target 60–70% accuracy. Fallback when LSTM confidence is low.

TensorFlow Lite / ONNX Runtime

Open framework

Used for on-device LSTM quantization and inference. INT8 post-training quantization reduces model from ~2 MB to ~500 KB while maintaining >98% of accuracy.

Perfetto Trace Analysis

Python + perfetto library to programmatically extract kernel-level sys_stats, memreclaim, am events. Bypassed the UI for reproducible automated extraction from raw .pftrace files.

🤖

LSTM on Real Device Data

PyTorch LSTM trained on authentic Samsung S23 / S31 FE / Nothing 2a traces. INT8 quantized via ONNX for simulated on-device inference within 3ms latency budget.

📊

Adaptive Cache Scoring

Custom ML-scored eviction policy (freq + recency decay + predicted next access) replacing static LRU. Cache manager uses LSTM output directly to inform eviction decisions.

Key Processes & Best Practices

P1
Held-out test traces: All KPI numbers measured only on traces never seen during threshold calibration or model training
P2
Cumulative PSI → delta conversion: PSI values are nanosecond totals; we compute Δ(psi[t] - psi[t-1]) to get instantaneous pressure rate
P3
Conservative fallback by design: System never preloads under uncertainty. Reduces wrong preloads that worsen pressure.
P4
Real device ADB measurement: am start -W gives true millisecond TTI from the kernel, not estimated latency

Creative Use of AI Tools

AI-Assisted Synthetic Data Augmentation

With only ~40 real launch events across 3 devices, we use structured augmentation: shuffle app sequences, jitter launch times ±15%, cross-device pooling. Produces 500+ training windows from 40 real events.

PSI as an LLM-style "Attention Signal"

We treat PSI stall time analogously to attention weights — high PSI = the system is "attending" to a memory crisis. The second derivative (PSI acceleration) predicts impending kill storms 2–3 seconds before they hit.

Deployment path (production vision)

Near-term: Privileged Android Service

CAMAS deploys as a privileged system service registered with ActivityManager — similar to how Google's LMKD daemon operates. Hooks into ComponentCallbacks2.onTrimMemory() for real-time signals.

Long-term: OEM Integration

Samsung One UI kernel layer integration. LMKD plugin replacing static OOM adj with CAMAS's ML-scored priority queue. On-device model runs on Hexagon NPU (<3ms inference).
